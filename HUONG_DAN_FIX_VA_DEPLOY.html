🔧 Phần 2: Các Fix Code Quan Trọng

2.1. Fix Desktop Build Errors

⚠️ Vấn Đề Ban Đầu

Desktop project không build được vì:

  • Duplicate files: Services/, Configuration/ đã có trong Core
  • Include cả TrainingB.Web/ folder gây conflict
  • Scrapers trong Forms/Test/ trùng với Core

1Sửa file TrainingB.csproj:

<Project Sdk="Microsoft.NET.Sdk"> <PropertyGroup> <OutputType>WinExe</OutputType> <TargetFramework>net8.0-windows7.0</TargetFramework> <UseWindowsForms>true</UseWindowsForms> </PropertyGroup> <!-- QUAN TRỌNG: Exclude các files duplicate --> <ItemGroup> <Compile Remove="Forms\Test\**" /> <Compile Remove="Services\**" /> <Compile Remove="TrainingB.Web\**" /> <Compile Remove="TrainingB.Core\**" /> </ItemGroup> <!-- Reference Core library để dùng Scrapers --> <ItemGroup> <ProjectReference Include="TrainingB.Core\TrainingB.Core.csproj" /> </ItemGroup> <ItemGroup> <PackageReference Include="Selenium.WebDriver" Version="4.25.0" /> </ItemGroup> </Project>
✅ Kết Quả

Desktop project build thành công, dùng compiled DLL từ TrainingB.Core thay vì source code trực tiếp.

2.2. Fix Desktop App Load Scrapers

⚠️ Vấn Đề

Code cũ dùng Assembly.GetExecutingAssembly() → Chỉ tìm scrapers trong Desktop project

Nhưng giờ Scrapers đã chuyển sang TrainingB.Core.dll

2Sửa file Forms/FormMonitor.cs:

// CŨ (SAI): var ls = Assembly.GetExecutingAssembly().GetTypes() .Where(a => a.IsSubclassOf(typeof(FindBase))) .ToList(); // MỚI (ĐÚNG): var coreAssembly = typeof(FindBase).Assembly; // Lấy assembly chứa FindBase var ls = coreAssembly.GetTypes() .Where(a => a.IsSubclassOf(typeof(FindBase)) && !a.IsAbstract) .ToList();

Thay đổi này cần áp dụng cho TẤT CẢ các function:

  • ProcessAllScrapers() - Chạy tất cả scrapers
  • MN_Load() - Chạy scrapers Miền Nam
  • HN_Load() - Chạy scrapers Miền Bắc
  • LoadScrapersByFilter() - Chạy scrapers theo filter

2.3. Fix Selenium Version Conflict

⚠️ Vấn Đề

Selenium.WebDriver version 4.35.0 bị corrupt hoặc không tương thích với .NET 8.0

3Downgrade về version ổn định:

# PowerShell: cd D:\TrainingB # Remove version cũ dotnet remove TrainingB.Core/TrainingB.Core.csproj package Selenium.WebDriver # Add version 4.25.0 (stable) dotnet add TrainingB.Core/TrainingB.Core.csproj package Selenium.WebDriver --version 4.25.0 # Restore & Build dotnet restore dotnet build

2.4. Fix Chrome Trong Docker

⚠️ Vấn Đề Lớn Nhất

Chrome không chạy được trong Docker container vì:

  • Thiếu dependencies (xvfb, libgbm1, fonts, etc.)
  • Không có display server (X11)
  • Cần chạy headless mode
  • Cần disable sandbox (container restrictions)

4Sửa file TrainingB.Core/Services/WebDriverHelper.cs:

public static ChromeDriver CreateDriver() { var options = new ChromeOptions(); // Detect Docker environment bool isDocker = Environment.GetEnvironmentVariable("DOTNET_RUNNING_IN_CONTAINER") == "true" || File.Exists("/.dockerenv"); if (isDocker) { Logger.Info("Running in Docker, applying container-specific Chrome options"); // QUAN TRỌNG: Các flags này BẮT BUỘC trong Docker options.AddArguments( "--headless=new", // Headless mode (không cần GUI) "--no-sandbox", // Disable sandbox (Docker đã có isolation) "--disable-dev-shm-usage", // Dùng /tmp thay vì /dev/shm "--disable-gpu", // Disable GPU "--window-size=1920,1080" ); } var driver = new ChromeDriver(options); driver.Manage().Timeouts().PageLoad = TimeSpan.FromSeconds(60); driver.Manage().Timeouts().ImplicitWait = TimeSpan.FromSeconds(30); return driver; }

🐳 Phần 3: Chuẩn Bị Deploy với Docker

3.1. Tạo Dockerfile

File Dockerfile ở root folder của project:

# Use .NET 8 SDK for building FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build WORKDIR /src # Copy project files COPY ["TrainingB.Web/TrainingB.Web.csproj", "TrainingB.Web/"] COPY ["TrainingB.Core/TrainingB.Core.csproj", "TrainingB.Core/"] RUN dotnet restore "TrainingB.Web/TrainingB.Web.csproj" # Copy source code và build COPY . . WORKDIR "/src/TrainingB.Web" RUN dotnet build "TrainingB.Web.csproj" -c Release -o /app/build RUN dotnet publish "TrainingB.Web.csproj" -c Release -o /app/publish # Runtime image FROM mcr.microsoft.com/dotnet/aspnet:8.0 WORKDIR /app # QUAN TRỌNG: Cài Chrome và dependencies RUN apt-get update && apt-get install -y \\ wget \\ gnupg \\ ca-certificates \\ apt-transport-https \\ xvfb \\ libgbm1 \\ libnss3 \\ libatk-bridge2.0-0 \\ libx11-xcb1 \\ libxcb-dri3-0 \\ libdrm2 \\ libgbm1 \\ libasound2 \\ fonts-liberation \\ && wget -q -O - https://dl-ssl.google.com/linux/linux_signing_key.pub | apt-key add - \\ && echo "deb [arch=amd64] http://dl.google.com/linux/chrome/deb/ stable main" >> /etc/apt/sources.list.d/google-chrome.list \\ && apt-get update \\ && apt-get install -y google-chrome-stable \\ && rm -rf /var/lib/apt/lists/* # Copy published app COPY --from=build /app/publish . # Environment variable để detect Docker ENV DOTNET_RUNNING_IN_CONTAINER=true # Expose port EXPOSE 8080 ENTRYPOINT ["dotnet", "TrainingB.Web.dll"]
💡 Giải Thích Dockerfile
  • Stage 1 (build): Build .NET application
  • Stage 2 (runtime): Install Chrome + dependencies, copy built app
  • Multi-stage: Giảm image size (chỉ copy compiled app, không copy SDK)

🔧 Phần 6: Troubleshooting

6.0. Lỗi Concurrent Requests (2 người cùng chạy)

⚠️ Lỗi: Server crash khi nhiều người cùng sử dụng

Nguyên nhân:

  • 2+ users click scraper cùng lúc → Server tạo nhiều ChromeDriver instances
  • Free tier Render chỉ có 512MB RAM
  • Mỗi ChromeDriver dùng ~200-300MB → Out of Memory
  • Không có locking mechanism → Race condition

Giải pháp đã implement:

1Thêm Request Queue vào ScraperController.cs:

// Add ở đầu class: private static readonly SemaphoreSlim _scraperLock = new SemaphoreSlim(1, 1); private static bool _isScraperRunning = false; private static string _currentScraperName = ""; // Trong RunScraper method: [HttpPost("run/{scraperName}")] public async Task<IActionResult> RunScraper(string scraperName) { // Check nếu đang có scraper khác chạy if (_isScraperRunning) { return StatusCode(409, new { error = "Another scraper is currently running", currentScraper = _currentScraperName, message = $"Please wait for '{_currentScraperName}' to complete" }); } // Thử acquire lock (không đợi) if (!await _scraperLock.WaitAsync(0)) { return StatusCode(409, new { error = "Server is busy, please try again" }); } try { _isScraperRunning = true; _currentScraperName = scraperName; // ... run scraper code ... } finally { // Release lock _isScraperRunning = false; _currentScraperName = ""; _scraperLock.Release(); } }

2Update frontend (app.js) để handle 409 status:

else if (response.status === 409) { // Conflict - another scraper is running showStatus(`⏳ ${name}: Server đang bận`, 'error'); const message = data.message || `Scraper khác đang chạy`; resultsDiv.textContent = `[${timestamp}] ${name}: ${message}\n\n` + resultsDiv.textContent; }
✅ Kết Quả
  • Chỉ cho phép 1 scraper chạy tại 1 thời điểm
  • Requests khác nhận error 409 với message rõ ràng
  • User biết phải đợi scraper hiện tại hoàn thành
  • Không còn crash do out of memory
💡 Behavior Mới

Khi 2 người cùng click button:

  • User 1 (click trước) → ✅ Scraper chạy bình thường
  • User 2 (click sau) → ⏳ Nhận message: "Please wait for 'MN_4D_LO' to complete"
  • User 2 có thể click lại sau khi User 1 xong (1-2 phút)

Giải pháp:

# Kiểm tra TrainingB.csproj có exclude đúng: <Compile Remove="Forms\Test\**" /> <Compile Remove="Services\**" /> <Compile Remove="TrainingB.Core\**" /> <Compile Remove="TrainingB.Web\**" /> # Clean & rebuild: dotnet clean TrainingB.csproj dotnet build TrainingB.csproj

6.2. Desktop App Không Load Scrapers

⚠️ Lỗi: Click "Run" không có gì xảy ra

Nguyên nhân: Code dùng GetExecutingAssembly() thay vì load từ Core DLL

Giải pháp:

# Check Forms/FormMonitor.cs các function: # ProcessAllScrapers(), MN_Load(), HN_Load(), LoadScrapersByFilter() # Phải dùng: var coreAssembly = typeof(FindBase).Assembly; var ls = coreAssembly.GetTypes() .Where(a => a.IsSubclassOf(typeof(FindBase)) && !a.IsAbstract) .ToList();

6.3. Chrome Không Chạy Trong Docker

⚠️ Lỗi: SessionNotCreatedException

Nguyên nhân: Thiếu Chrome dependencies hoặc không dùng headless mode

Giải pháp:

  1. Check Dockerfile có cài đủ dependencies (xvfb, libgbm1, Chrome stable)
  2. Check WebDriverHelper.cs có detect Docker và add flags:
    • --headless=new
    • --no-sandbox
    • --disable-dev-shm-usage
  3. Check logs trên Render:
    • Dashboard → Your service → Logs
    • Tìm error message

6.4. Render Deploy Fails

⚠️ Lỗi: Build failed hoặc Deploy timeout

Các nguyên nhân thường gặp:

LỗiNguyên nhânGiải pháp
Build timeout Free tier có giới hạn thời gian build Upgrade lên paid plan hoặc optimize Dockerfile
Port binding error App không listen đúng port Check EXPOSE 8080 trong Dockerfile và app config
Permission denied Chrome không có quyền execute Add --no-sandbox flag
Out of memory Free tier có RAM hạn chế (512MB) Upgrade hoặc optimize code

6.5. NuGet Package Restore Errors

⚠️ Lỗi: project.assets.json not found

Giải pháp:

# PowerShell: cd D:\TrainingB # Restore packages dotnet restore TrainingB.sln # Hoặc trong Visual Studio: # Right-click Solution → Restore NuGet Packages

📝 Phần 7: Workflow Sau Này

7.1. Khi Cần Fix Bug Hoặc Thêm Feature

  1. Sửa code local (Desktop hoặc Web)
  2. Test local:
    # Test Desktop: dotnet run --project TrainingB.csproj # Test Web: dotnet run --project TrainingB.Web/TrainingB.Web.csproj --urls "http://localhost:5555"
  3. Commit & Push:
    git add . git commit -m "Fix: your description here" git push origin main
  4. Render tự động deploy (chờ 5-10 phút)
  5. Test trên production URL

7.2. Khi Cần Rollback

Nếu deploy mới có bug:

  1. Trên Render Dashboard → Your service → Manual Deploy
  2. Chọn commit trước đó (working version)
  3. Click "Deploy"

Hoặc dùng Git:

# Revert về commit trước: git revert HEAD git push origin main # Hoặc reset về commit cụ thể: git reset --hard COMMIT_HASH git push -f origin main

7.3. Monitor Logs

Luôn theo dõi logs để detect lỗi sớm:

  • Desktop: D:\TrainingB\logs\app-YYYYMMDD.log
  • Web Production: Render Dashboard → Logs tab
  • Web Local: Console output khi chạy dotnet run
